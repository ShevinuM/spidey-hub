Making `handleKey` return `void` would silently break keydown routing for every pane program in the app. A rule cannot require breaking the interface its own codebase is built on. **Second:** the file is verbatim-relocated (verified — only the move commit and the comment sweep touch it), so (e)'s standing rationale applies unchanged. Note this exemption is **about `handleKey`'s protocol-mandated shape, not a general licence**: a *new* method authored during migration that mutates and returns a value is still a violation. Whether `handleKey` is better hosted on the orchestrator component than on the state class — notifications puts it on the component, employment on the class — is a real inconsistency, but it is a hardening-pass question, not a migration one.
