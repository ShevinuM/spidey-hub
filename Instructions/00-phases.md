## Binding decisions (all phases; do not re-litigate — architecture.md R003)

- **D1 Strategy: bulk-import then restructure in place.** Per-feature e2e/visual needs a bootable app and nothing renders without the Terminal kernel, so v2 cannot be built up from empty. Pre-phase imports v1's whole working tree as a green baseline; later phases move code between contexts with the full suite as a gate. Consequence: `src/components/`+`src/lib/` exist transiently until phase 11 closes; structure audits are phase-scoped until then.
- **D2 toolchain.md R014 settled (user-approved 2026-08-29):** relative TS imports extensionless; `exactOptionalPropertyTypes: true`, `verbatimModuleSyntax: true`. Recorded in toolchain.md during pre-phase.
- **D3 Unit runner is Vitest** (toolchain.md R004). `checklist/testing/README.md` R001 and `docs/testing/e2e/structure.md` still say `node --test` — stale; swept in pre-phase (doc-practice R003/R006). v1's 19 unit tests port mechanically in pre-phase.
- **D5 Visual parity mechanism:** v1's capture pipeline (`pipeline.mjs` + `toMatchSnapshot`) is kept unchanged for the entire migration. Goldens seed from v1 byte-for-byte; `--update-snapshots` is forbidden. Converting to the docs' `toHaveScreenshot` is deferred (see Deferred).
- **D6 Playwright config:** one root `playwright.config.ts`. Pre-phase adds `smoke` (new) + `legacy` (v1's suite as-is). Each phase moves its specs out of `legacy` into its own `<context>` / `<feature>-visual` project entries, added only when the spec folder exists (architecture R002). `legacy` is deleted when it empties (phase 11).
- **D7 Fixture split mapping is fixed here** (per-phase execution): repositories→`fixtures/{repositories,repos,commits}`; employment→`fixtures/personnel`; dashboard→`fixtures/contributions.json`; grep→`fixtures/grep-index.json`; shell-fs→`fixtures/fs-index.json`. Loader/build-script path updates per D22.
- **D8 Literal-path assertions** (grep.spec, shell.spec, any spec asserting real tree paths): updated **in the same change** as the move that invalidates them. `GREP_ROOT_SUBDIRS`/`FS_INDEX_SUBDIRS` stay valid (everything remains under `src/`). No known-red state is ever carried between phases.
- **D9 Editor is common** (repositories + employment previews consume it): `vim.ts` → `common/engines/vim/`, editor components + `editorRender` → `common/components/editor/`, `pasteBuffer.ts` → `common/lib/` (editor + copy-mode). Moves in phase 02.
- **D10 Kernel homes:** `tmux.ts` → `common/engines/tmux/`; chrome (StatusBar, Meter, PaneTree, PanelBadge, Wallpaper, Cmdline, CopyMode, ChooseTree) → `common/components/`; `clock/views/layout/pasteTargets/cmdline/data`.ts → `common/lib/`; Terminal.svelte + terminalState + `layouts/Shell.astro` (renamed `Layout.astro`, D13) → `src/bootstrap/`. **`src/pages/*.astro` and `src/content.config.ts` cannot move — Astro hard-codes both**; pages are thinned to import only from `bootstrap/` (architecture R008); `content.config.ts` aggregates feature-exported collection definitions (R005). Kernel + editor specs → `common/tests/ui/e2e/` under a single `common` project.
- **D11 helpSearch → fuzzysort** (delegate.md): separate, test-verified step inside phase 04, only after the verbatim move is green. Bespoke parts kept: two-shaped corpus, commands-before-keymaps tie-break. Golden-freeze constraint: recipe `20-help-search` renders a fixture query's results — the swap is allowed only if the help visual passes with zero golden churn; otherwise the executor reports back and the swap joins the Deferred list (post-rebaseline). Deliberate `help-search.spec.ts` assertion changes isolated in the swap's own commit.
- **D15 Renames during moves:** plain lib `.ts` → kebab-case at the new home (`bootState.ts` → `boot-state.ts`); state classes keep `<name>State.svelte.ts`; components PascalCase. No `types.ts` or barrel `index.ts` may be carried over (files-and-naming R005/R008 — split by concept during the move). Imports updated in the same change.
- **D16 Rule-of-three:** promote to `common/lib/` only with ≥2 verified real consumers (grep before promoting). Known multi-consumer: `resume.ts` (profile + cmdline), `pasteBuffer.ts`, `docline.ts` (verify at move time). Single-consumer modules go to the owning feature's `lib/`.
- **D17 data.ts / yaml:** `data.ts` → `common/lib/data.ts` in phase 02 with its glob widened to span `src/data/` + `src/common/content/` + `src/features/*/content/`; each feature phase moves its own yaml; the `src/data/` leg is removed when the last yaml leaves (phase 11 closes it out — `site/choosetree/cmdline.yaml` move in phase 02 with the kernel).
- **D18 `exactOptionalPropertyTypes` checkpoint:** if enabling surfaces >~50 type errors in pre-phase, the executor reports the count and stops for orchestrator review.
- **D19 package.json `name` stays `shevinum-dev-v3`** (its text is grep-indexed); rename deferred.
- **D20 Every full-suite gate is TWO invocations:** (a) real build (`E2E_EXPECT_FIXTURES=0`) → smoke + all e2e projects; (b) fixture build (`E2E_EXPECT_FIXTURES=1`, `build:fixtures`) → all `*-visual` + legacy visual. One server, one `dist/`, env-gated; `tests/checkFixtureFlag.ts` fails mismatches by design. Mirror v1's `test:e2e`/`test:visual` split.
- **D21 Visual mechanics settled once, by the FIRST golden-seeding phase (02 or 03, whichever runs first), reused verbatim by every later phase:** (a) v1's `snapshotPathTemplate` assumes `{projectName}` = viewport; per-context project names break that — pick the template + viewport handling that reproduces `.../goldens/<viewport>/<recipe>.png` byte-identically; (b) the shared visual/test infra gets its permanent home in the same step: `pipeline.mjs`, `recipes.ts` (viewports, `CLOCK_TIME`), `static-server.mjs`, `capture-goldens.mjs`, `checkFixtureFlag.ts`, and the vendored `tests/visual/reference/` move to `common/tests/ui/support/` (testing README R002) — before splitting anything, the executor reads `identical.spec.ts`/`adversarial-fixtures.spec.ts` to learn what the port-4400 reference server actually compares against (if "identical" targets the vendored prototype rather than goldens, the split mechanics change — report the finding). Both (a) and (b) are recorded in `Instructions/01-pre-phase/recipe-feature-map.md`; phase 11's remnant-delete list is then empty by construction.
- **D22 `fixtures/` files are build inputs:** `content.config.ts` fixture-switches and `build:fixtures` copy **sources** update in the same change as any fixture move.
- **Legacy-tree fallout rule:** every phase may make *mechanical* edits outside its context (import paths in the legacy tree/specs, literal-path assertions per D8, one Playwright project entry, `content.config.ts`/`build:fixtures` paths per D22) — declared in its PLAN.md. Behavioral edits outside the context are never in scope.
- **D23 Audit exemptions during migration** (tracked, not permanent — test-setup.md's per-feature exemption): an auditor "no" verdict does **not** block phase close only when it is (a) a POM/locator/spec-convention rule (`e2e-testing.md` R003–R010, `playwright.md` locator rules) hitting a verbatim-ported spec, (b) architecture R009's missing fitness test, or (c) a structure rule hitting the transient legacy tree (`src/components`/`src/lib`) rather than this phase's context. Each exempted "no" is recorded in the phase folder's audit report with the exemption named. Every other "no" blocks.
