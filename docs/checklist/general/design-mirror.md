# Claude Design mirror

Rules for `ds-bundle/`, the self-contained page-mirror export pushed to Claude Design. Mechanics carried over from v1's `scripts/generate-design-mirror.mjs` unchanged; the pinned project identity is v2-specific (see R008).

## What it is

- [ ] **R001** The mirror is not a component design system — it's whole rendered pages, one self-contained `.dc.html` snapshot per route per build (a real-content build and a fixture-content build), generated by `scripts/generate-design-mirror.mjs`.
- [ ] **R002** The generator runs both the real build and the fixture build, serves each on a scratch port, and for every route `bootstrap` composes (each already its own page with its own default state) navigates directly to it — no keystroke replay needed. It waits for the app's own "ready" signal plus fonts/network idle, then serializes the hydrated DOM into the snapshot.

## Self-containment

- [ ] **R003** Every `<script>` tag is stripped from the serialized output — the mirror is a static snapshot, never a live page.
- [ ] **R004** Every same-origin asset the page actually references (images, fonts, build-hashed font-subset files) is inlined as a base64 `data:` URI so the file renders standalone from `file://` with zero network requests. Discover what needs inlining by fetching whatever the live server actually returns for any remaining absolute asset reference — not by hand-enumerating known asset paths; v1 learned this the hard way when an enumerated list missed build-hashed font subsets the bundler emits as external files. Fetch-and-inline-whatever-resolves is correct by construction; an enumerated list silently rots the next time the build tool changes what it emits.
- [ ] **R005** A large binary asset (multi-megabyte image) is the one deliberate exception to R004 — emit it as a sibling file next to the generated `.dc.html` and reference it by a relative path instead of inlining it, so a single large file doesn't get duplicated into every snapshot that uses it.
- [ ] **R006** Confirm a regenerated page still renders standalone from `file://` with zero failed network requests before pushing it.

## Output & config

- [ ] **R007** Output goes to `ds-bundle/pages-real/` and `ds-bundle/pages-fixtures/` — gitignored, never committed.
- [ ] **R008** The pinned target lives in `.design-sync/config.json`: `projectId: "7843b461-c831-40a6-9e98-384d79d380c8"`, `projectName: "SpideyHub v2"`, `shape: "page-mirror"`. Created empty — v1's project ("SpideyHub", `projectId 1fe80714-74c4-47b7-9975-76a8f686f91d`) does not carry over, so this one gets populated by running `scripts/generate-design-mirror.mjs` against v2's own code once that exists, not by copying v1's snapshots.
- [ ] **R009** Never create a second project for the mirror once R008 is settled — one pinned project, always pushed to.

## Pushing

- [ ] **R010** Push with the `DesignSync` tool: `finalize_plan` (`localDir` = `ds-bundle/`), then `write_files` in batches.
- [ ] **R011** Always push both builds' page sets together (`pages-real/**` and `pages-fixtures/**`) — they're the same routes over different data, and a half-pushed mirror (one build updated, the other stale) is worse than a stale one.
- [ ] **R012** Regenerating and re-pushing the mirror is not optional after any change that alters what a page renders — it ships in the same change as the rendering change, never as a follow-up. Enforced by a pre-push ritual, run in this order immediately before pushing `frontend-rewrite`: (1) `pnpm design-mirror`, regenerating both `ds-bundle/pages-real/` and `ds-bundle/pages-fixtures/` from the tree about to be pushed; (2) `grep -c "<script" ds-bundle/pages-real/*.dc.html ds-bundle/pages-fixtures/*.dc.html` — every file must report `0` (R003); (3) open one regenerated page per build from `file://` and confirm zero failed network requests (R006); (4) push both sets together with the `DesignSync` tool (R010/R011). A push not immediately preceded by a green (1)–(3) is the exact drift this rule exists to catch. This is a documented developer ritual, not a CI step — nothing in this repo runs it automatically yet.
